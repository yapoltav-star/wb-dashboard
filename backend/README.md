# Backend

`main.py` — FastAPI, источники WB, расписания и маршруты. `site_auth.py` —
общая защита сайта. `frontend/` — копия интерфейса для Railway с корнем backend.

`boost_monitor.py` сохраняет ежедневные позиции в существующей таблице
Supabase `settings`, по отдельному ключу `boost_rank_v1:дата:группа`.
Конфигурация: `boost_monitor_targets.json`, исходник — boost-report.xlsx за
16–22 ноября 2026. Ключи рекомендаций — метаданные задания: место измеряется
по паре товар/карточка-источник, а не повторно для каждого ключа.

Замер: 10:00 Europe/Moscow. После запуска сервера — догрузка сегодняшних
недостающих замеров, затем каждый час повтор ошибок. Успешная группа за день
не перезаписывается. Внешний cron и открытый браузер не нужны; сервер должен
работать постоянно в одном процессе, как задано в nixpacks.toml. Новая миграция
не требуется. Нельзя запускать несколько реплик без распределённой блокировки.

API под общей авторизацией:
- GET `/api/boost-position-history?date_from=2026-11-23&date_to=2026-11-30`
  — точные даты, дневная история и сопоставимость (интервал до 31 дня).
- POST `/api/boost-position-capture` — фоновый повтор недостающих/ошибочных групп.

Сохраняются город, глубина, фактически проверенные места, тип выдачи, время,
позиция или явная ошибка. Сменившиеся источники не сравниваются. Пустой ответ
или ошибка страницы не считаются отсутствием товара. История прошлых дней
не восстанавливается; старые записи не удаляются. Для новых заданий обнови
конфигурацию с неизменным ID существующей группы и новыми товарами в новой группе:
успешный снимок группы текущего дня неизменяем. Исторические названия сохраняются
в снимках. Артикул продавца показывается перед номером WB.

Проверка результата: открыть историю, сверить покрытие 201 связки, раскрыть время
и источник у строки, перезагрузить страницу и проверить тот же снимок. При сбое
WB — дождаться часового повтора; при ошибке хранения проверить Supabase. Решения
о бустах принимает владелец после сопоставления позиций с рекламой, остатками,
ценой и заказами. Изменение позиций не доказывает причинность.

`railpack.json` добавляет системный curl с HTTP/2 в runtime, сохраняя стандартные пакеты Railpack; он нужен для чтения основного блока полок. Аналогичная зависимость указана в nixpacks.toml для старого сборщика. [Документация Railpack](https://railpack.com/guides/installing-packages/).
